module seam problem / leak deep module

Collapse the Totals math into one deep module

Strong

src/util/tax.ts:1 · order-overview/page.tsx:39 · OrderListTotals.tsx:36 · useGroupedSubmittedOrders.ts:55 · HostPastEventCard.tsx:23

Problem
The same subtotal × tax math is reimplemented at four call sites — and in two different forms: TAX_RATE (add) at OrderListTotals.tsx:45 & useGroupedSubmittedOrders.ts:60, TAX_MULTIPLIER (multiply) at order-overview/page.tsx:40 & HostPastEventCard.tsx:23. tax.ts exports two constants and nothing else — the math is the caller's problem.
Solution
One Totals module takes orders, returns { subtotal, tax, total }. Callers read a number; rounding and rate live in one place.
  • locality: rate change, one edit
  • leverage: one interface, 4 callers
  • now testable at one surface
  • kills the RATE-vs-MULTIPLIER drift

Move the "host doesn't pay" rule behind the Totals interface

Strong

src/util/orderGrouping.ts:28 · order-overview/page.tsx:35 · useGroupedSubmittedOrders.ts:56 · useHostPastEvents.ts:88

Problem
excludeHostOrders encodes a money rule — the host collects but never owes — yet it is called from exactly one site (order-overview/page.tsx:35). The kitchen total in useGroupedSubmittedOrders.ts:56 and the past-event grand total in useHostPastEvents.ts:88 sum every order, host included — silently inflating two of the three totals a host sees.
Solution
Fold host-exclusion into the same Totals module. Pass hostId once; no caller can forget to apply the rule.
  • locality: the rule has one home
  • leverage: callers can't skip it
  • removes a silent over-charge path
  • deletion test: rule reappears in 3 callers

Lift the collected-vs-pending math out of the page

Worth exploring

src/app/order-overview/page.tsx:35-45

Problem
The single most important financial state — how much is still owed — is six lines of arithmetic living inside a page render function (order-overview/page.tsx:35-45). It can't be reused, can't be tested, and Math.max(0, …) at :45 hides any negative-pending bug instead of surfacing it.
Solution
A useCollection hook (built on the Totals module) returns { collected, pending }. The page renders; it stops computing.
  • now testable at one surface
  • leverage: reusable on a dashboard
  • locality: collection rule in one hook
  • can assert pending ≥ 0 honestly

Give the attendee an identity module instead of one expression copied 5×

Strong

useOrders.ts:75 · useAddOrderForm.ts:29 · order/page.tsx:34 · OrderList.tsx:48 · orders/OrderListItem.tsx:46

Problem
Who an attendee is — user.full_name || user.email || guestName — is copy-pasted at five sites. That string is the join key for grouping orders and for the "is this attendee paid?" check, so any one site drifting changes who owes what. There is no module that owns attendee identity.
Solution
One currentAttendeeName(user, guestName) resolver. Every order, total, and paid-check reads the same key from one place.
  • locality: identity has one home
  • leverage: 5 callers, one rule
  • join key can't drift per-file
  • now testable at one surface

Money & auth run with no test surface — and a live signOut bug

Strong

no *.test.* in repo · AuthContext.tsx:6 · useOrders.ts:129 · eventService.ts:63

Problem
The repo has no test tooling and no test files, so every money and auth path is unverified. Two are concrete: AuthContext.tsx:6 imports the default export of next/router in an App Router app — signOut's router.push("/") at :65 throws at runtime; and setAttendeePaid at useOrders.ts:129 flips is_paid by name with no host check (only deleteEvent at eventService.ts:82 verifies the host).
Solution
Fix the import to useRouter from next/navigation; the deepening in cards 1–3 turns money into pure modules you can table-test. Confirm RLS guards is_paid server-side.
  • risk: untested money + auth
  • concrete: signOut throws
  • deepening makes math testable
  • verify is_paid authority server-side
