Where the two drafts diverged — and who was right

Visual review got these, prose missed them

  • The signOut / next/router runtime bug — a real crash.
  • Host-exclusion applied at only one of three totals (silent over-charge).
  • setAttendeePaid with no host authority check.
  • Attendee identity as a first-class scattered concept.

Prose review got these, visual missed them

  • The duplicated order-intake writers (addOrderUtil vs addMutation).
  • The two duplicated past-events fetchers.
  • The cutoff parsing inconsistency.
  • OrderList's phantom dual-mode interface.

Claims to retire

  • "Pages call supabase directly" (prose #2) — they don't.
  • "Two cutoff gates" — there is one gate; the other parser is display-only.
  • "5×" identity (visual #4) undercounts — it's ~8.
  • OrderListItem re-absorb (prose #6) — true but cosmetic; not in the plan's critical path.

The drafts were complementary, not contradictory. The visual review was better at correctness/security bugs; the prose review was better at duplication/structure. The synthesis below keeps the bugs first.

The single root cause

There is no module that owns money, and none that owns identity.

Every confirmed money bug — tax-rate drift, host included in two of three totals, no-tax past-event totals, hidden Math.max(0, pending) — is the same failure: arithmetic is re-derived at each call site instead of computed once behind an interface. The identity bug is the mirror image: the join key that decides who owes what is an inline expression in ~8 files. Fix the two seams and most of the list collapses.

The final plan

Sequenced so each step makes the next safer. Steps 0–1 are cheap and stop active bleeding; 2–4 build the two seams; 5–7 lean on them; 8 is optional cleanup.

Step 0 · bug

Fix the signOut crash

Replace import router from "next/router" in AuthContext.tsx with useRouter from next/navigation, called inside the provider. One line of cause, a guaranteed runtime throw on every sign-out. No reason to wait.

src/contexts/AuthContext.tsx:6, :65

Step 1 · security

Confirm who may flip is_paid

The client sends an update keyed only on (event_id, user_name). If Supabase RLS does not already restrict orders.is_paid writes to the event's host, any authenticated user can mark anyone paid. Verify the policy in the dashboard; add one if missing. This is a data-integrity hole independent of the refactors.

src/hooks/useOrders.ts:129-147 · cross-check src/lib/eventService.ts:63,82

Step 2 · seam

Build the Totals module

One pure module: computeBill(orders, { hostId, onlySubmitted }) → { subtotal, tax, total, collected, pending }. It owns the tax rate, host-exclusion, the submitted filter, the paid/unpaid split, and rounding. This single module fixes three confirmed bugs at once: rate-vs-multiplier drift, host-included totals, and the no-tax past-event totals.

new: src/util/totals.ts · folds in tax.ts + the collection math from order-overview/page.tsx:35-45

Step 3 · seam

Build the identity resolver

One function: attendeeName(user, guestName) returning the canonical user_name. Every order write and every grouping/paid lookup reads it. Eliminates the ~8 inline copies of the fallback chain, and makes the grouping key impossible to drift per-file.

new: src/util/attendee.ts · callers at useOrders:75, useAddOrderForm:29, order/page:34, OrderList:48, OrderListItem:46, usePastEvents:28, reorderUtils:31/70, orderUtil:32/109

Step 4 · tests

Add the first test surface

Add Vitest (lightest setup for a Next 15 / TS repo). Table-test computeBill (tax rounding, host exclusion on/off, all-paid, partial-paid, empty) and attendeeName (user / email-only / guest / collision). This is the repo's first test — and steps 2–3 were designed to be pure so this is trivial.

new: src/util/totals.test.ts, src/util/attendee.test.ts · add vitest + script to package.json

Step 5 · adopt

Route every total through the module

Replace the inline arithmetic in order-overview/page.tsx, OrderListTotals.tsx, useGroupedSubmittedOrders.ts, and HostPastEventCard.tsx with calls to computeBill. Delete the bare TAX_RATE/TAX_MULTIPLIER imports at the call sites. After this the host-exclusion and no-tax bugs cannot recur.

edits across the 4 totals call sites + tax.ts becomes internal

Step 6 · adopt

Merge the two past-events fetchers

One hook usePastEvents(scope: "mine" | "hosted"). The join string, the event_date < today filter, and grouping (via the shared groupOrdersByUser) live once; totals come from computeBill, so the no-tax/host-included discrepancies vanish. Deletes ~100 duplicated lines.

merge src/hooks/usePastEvents.ts + src/hooks/useHostPastEvents.ts

Step 7 · adopt

Collapse order intake to one writer

Make useOrders' React-Query mutation the single insert path; fold addOrderUtil (used by useAddOrderForm) into it so the join string and cache invalidation live in one place. Keep reorderUtils only if its bulk insert genuinely differs; otherwise route it through too. (Note: contrary to the prose draft, no page writes directly — scope is the three util/hook writers, not the pages.)

src/hooks/useOrders.ts:63-91 · src/util/orderUtil.ts:20-48 · src/hooks/useAddOrderForm.ts:86 · src/util/reorderUtils.ts

Step 8 · optional

Cleanups, lowest leverage last

  • Cutoff parse: have timeUtils.calculateCutoffTimeString reuse cutoffUtil's local-parse (or share one parser) so the create/edit preview matches the gate.
  • OrderList: drop the unused orders/loading/error props — no caller passes them — and let the hook be the one source.
  • OrderListItem fragments: inline the sub-30-line display pieces only if no reuse is planned. Cosmetic; no correctness impact.

Do this first

Step 0 today, then build the Totals module.

Both drafts agreed the Totals module is the keystone, and verification confirms it — but the visual review surfaced a shipping crash (signOut) and a silent over-charge / auth hole that the prose draft never saw. Land the two one-step fixes first (they are independent and cheap), then build computeBill: it is the deepest concept in the app, the most scattered, and the seam that steps 5–7 all lean on. It also gives the repo its first real test surface.
